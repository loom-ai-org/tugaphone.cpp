# Parity with the Python tugaphone

This port gives the same bytes as the Python package tugaphone 1.4.16a1 for each function it ports. The parity test proves this. It runs every golden record in C++ and compares the result with the Python output, byte for byte.

## How parity is tested

The goldens are in `tests/goldens/<module>.jsonl.gz`, one file for each module. `tools/dump_goldens.py` writes them with the reference interpreter, and `tools/goldens/<module>.py` holds the corpora for each module. Each record holds the inputs of one call and the Python output. An exception is recorded as its Python class name.

The corpora for each module are these:

- Every string literal of the reference tests, read from the tag `1.4.16a1`.
- Every dialect and lect code, with case variants and aliases.
- A rule-coverage set built from the module tables.
- Unicode probes and a seeded fuzz set.

The test `tugaphone_parity` prints one line for each module, such as `registry: 797 in, 797 checked, 0 mismatches`. The test fails if a record has a mismatch, or if the number of records checked is not the count in the header.

The header of each golden file names the reference versions:

| --- | --- |
| tugaphone | 1.4.16a1 |
| tugalex | 2.2.2a1 |

## Python semantics the port keeps

Text is decoded to code points. `len`, indices and slices count code points. Ill-formed UTF-8 decodes to one U+FFFD for each maximal subpart, as `bytes.decode("utf-8", "replace")` does.

The case mappings, `isspace`, `isalpha`, `isupper`, `isdigit`, `isdecimal` and the regular-expression classes `\w` and `\d` come from tables. `tools/gen_unicode_tables.py` generates the tables from the reference interpreter, which uses Unicode 15.0. The port does not use ICU for these properties.

Each regular expression is ported as code that tries the alternatives in the same order as the Python engine. `int()` and `float()` accept the same text as Python. This includes Unicode digits, underscores between digits, surrounding whitespace, and `inf` or `nan` in any case. `int()` refuses more than 4300 digits. A float is written as its `repr`.

A Python set is a `std::set`, so the C++ set iterates in code-point order. The Python order depends on the hash seed, so the goldens write sets sorted.

## Data files

The data files are copied verbatim from the Python package. `set_data_dir()` or the environment variable `TUGAPHONE_DATA_DIR` selects another directory. `data/dialects.json` is generated by `tools/gen_dialect_data.py`. It holds the literal default of each dialect table and the entries each national class adds to the AO1990 tables. The generator rebuilds each class from the file and stops if the result is not the Python value.

## Python defects kept for parity

The port keeps these defects of the reference release, because it is held at byte parity:

- ovos-number-parser drops the feminine after a scale group: feminine 1001 reads "mil e um".
- ovos-number-parser keeps the masculine count before a feminine ordinal scale word: feminine ordinal 2002 reads "dois milésima segunda".
- ovos-number-parser compares the language code with its case, so "PT-PT" raises NotImplementedError.
- `EuropeanPortuguese` and `BrazilianPortuguese` replace an empty `IRREGULAR_WORDS` with the lexicon map. The African and Timorese classes keep an empty map.
